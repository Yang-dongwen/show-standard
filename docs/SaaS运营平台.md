# SaaS 运营平台

> 状态：一期 Web 运营台已落地。  
> **SaaS 与 C 端是两套产品**：前端、鉴权、URL 隔离；**共用同一数据库**。  
> 产品原则见 [产品双轨说明.md](./产品双轨说明.md)。进度见 [实现进度.md](./实现进度.md)。

## 1. 边界

| 系统 | 定位 | 用户 | 代码 | 入口 |
|------|------|------|------|------|
| **C 端** | 门店会员收银 | 店长/店员 | `com.ddmo.app` + `frontend/` | `/`、桌面安装包 |
| **SaaS** | 多租户运营 | 平台运营 | `com.ddmo.saas` + `frontend-saas/` | `/saas/` |

```text
C 端 Web/桌面  →  /api/**（店长 JWT）     → 业务表 + t_tenant
SaaS 运营台    →  /api/saas/**（SaaS JWT） → t_tenant / 邀请码 / 只读汇总业务
```

### 硬性规则

1. 禁止在 C 端前端挂 SaaS 页面。  
2. 禁止 Token 跨系统调用对方 API。  
3. SaaS 不复制收银业务逻辑；需要数据时查共享表。  
4. 开店（邀请码建租户）归属 SaaS；C 端注册主要服务单机模式。  

## 2. 存在意义（一句话）

| 端 | 定位 |
|----|------|
| **C 端** | 单店会员收银（业务深度） |
| **SaaS** | 多店开通、管控、经营总览、套餐与运营（平台广度） |

C 端再强也不能代替「谁能开店 / 是否到期 / 全网汇总」；SaaS 只有开店也不能代替收银。

## 3. 功能分层

| 层级 | 内容 | 状态 |
|------|------|------|
| **L1 管控** | 邀请开店、租户启停、配额、单店摘要 | 已落地 |
| **L2 运营中台** | 驾驶舱、租户档案、重置密码、审计、公告、套餐目录 | 已落地 |
| **L3 商业化** | 到期拦截、人工续期账单、只读模式 | 主体已落地 |
| **L4 联动** | 服务热度、到期列表、门店码提示等 | 部分；会员小程序/卡项汇总后置 |

**原则：** 收银细节继续在 C 端做深；跨店与计费在 SaaS 做宽；**不把收银页搬进 SaaS**。

## 4. API 摘要

| 系统 | 前缀 | 鉴权 |
|------|------|------|
| C 端 | `/api/**` | JWT `typ=manager` + `tenant_id` |
| SaaS | `/api/saas/**` | JWT `typ=saas` |

SaaS 主要接口：登录、公开开店、租户列表/详情/启停/套餐、邀请码、驾驶舱与运营动作等（以代码与 [实现进度.md](./实现进度.md) 为准）。

## 5. 前端

| 工程 | 产物 | 访问 |
|------|------|------|
| `frontend/` | `static/` | `/` |
| `frontend-saas/` | `static-saas/` | `/saas/` |

```powershell
cd frontend ; npm run dev          # :3000
cd frontend-saas ; npm run dev     # :3001 → /saas/
```

SaaS 示例账号：`platform` / `platform123`（见 `application.yml`）。
