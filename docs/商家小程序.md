# 商家微信小程序 V1

> 状态：工程已落地（`miniprogram-biz/`）；正式域名与提审视部署情况。  
> 产品原则见 [产品双轨说明.md](./产品双轨说明.md)。  
> **前提：必须云版**；本地安装包不连小程序。

## 1. 为什么必须云

1. 微信要求 **HTTPS 公网** request 域名  
2. 不能访问店内 `localhost`  
3. 多店与套餐在云库 + SaaS  

本地版：`app.deployment=desktop`，小程序关闭。

## 2. 架构

```text
商家小程序  --HTTPS-->  云 API /api/**
                          |
                     JWT typ=manager
                          |
                   与 C 端 Web 同一套领域服务
```

**V1 不复制业务接口**，直接调用现有 C 端 REST。

## 3. 页面与 C 端对照

| 小程序 | C 端 | 主要 API |
|--------|------|----------|
| 登录 | Login | `POST /api/auth/login`、微信绑定登录 |
| 首页 | Dashboard | `GET /api/reports/dashboard` 等 |
| 会员 | Customers | `/api/customers` |
| 收银 | Transactions | 充值/消费相关 |
| 员工 / 服务 / 报表 / 门店 | 对应页 | `/api/employees`、`/api/config/services`、`/api/reports/**`、`/api/shop` |

> Web 端已支持 **店长 / 收银员 / 店员** 角色；小程序仍用同一 JWT，后端 `PermissionInterceptor` 会按角色拦截无权限接口。小程序侧菜单按角色隐藏可后置。

## 4. 本地开发

1. 后端启动（开发可用 mock 微信）  
2. 微信开发者工具打开 `miniprogram-biz/`  
3. `utils/config.js` 配置 `baseUrl`（如 `http://127.0.0.1:8080`）  
4. 开发工具勾选：不校验合法域名  

正式环境见 [云版Docker部署.md](./云版Docker部署.md)。

## 5. 微信相关接口

| 接口 | 说明 |
|------|------|
| `POST /api/auth/wx-login` | code → 已绑定发 JWT / 否则 preToken |
| `POST /api/auth/wx-bind` | 绑定店长账号 |
| `GET /api/auth/wx-bind-status` | 是否已绑定 |
| `POST /api/auth/wx-unbind` | 解绑 |

`mock: true` 时不访问微信服务器，便于联调。
